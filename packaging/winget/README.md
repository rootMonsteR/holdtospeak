# winget manifest

Manifests for publishing HoldToSpeak to the [Windows Package Manager Community
Repository](https://github.com/microsoft/winget-pkgs), so that `winget install HoldToSpeak` works.

```
rootMonsteR.HoldToSpeak/<version>/
  rootMonsteR.HoldToSpeak.yaml               version manifest
  rootMonsteR.HoldToSpeak.installer.yaml     installer URL + SHA-256
  rootMonsteR.HoldToSpeak.locale.en-US.yaml  name, description, licence, tags
```

Keeping these in-repo means the submitted manifest is reviewable and version-controlled rather
than generated by hand at submission time and then lost.

## Publishing a version

The manifest points at a **GitHub Release asset**, so the release must exist and be public first —
the `InstallerUrl` is fetched and hashed by Microsoft's validation pipeline.

1. Build and cut the release (`packaging/build-installer.ps1`, then attach both artifacts to a
   `v<version>` tag).
2. Copy the previous version directory to the new version number and update, in all three files:
   `PackageVersion`, and in the installer manifest the `InstallerUrl`, `InstallerSha256`
   (`Get-FileHash <setup.exe> -Algorithm SHA256`) and `ReleaseDate`; and in the locale manifest
   the `ReleaseNotesUrl`.
3. Validate locally — this catches schema errors before a PR is opened:
   ```powershell
   winget validate --manifest packaging/winget/rootMonsteR.HoldToSpeak/<version>
   ```
4. Submit a PR to `microsoft/winget-pkgs` placing the directory at
   `manifests/r/rootMonsteR/HoldToSpeak/<version>/`. The
   [wingetcreate](https://github.com/microsoft/winget-create) tool automates the fork/PR:
   ```powershell
   winget install --id Microsoft.WingetCreate --exact
   wingetcreate submit --token <github-pat> packaging/winget/rootMonsteR.HoldToSpeak/<version>
   ```

## Notes on the fields

* **`InstallerType: inno` + `Scope: user`** — the installer is per-user
  (`PrivilegesRequired=lowest`), so winget installs it without an elevation prompt. winget already
  knows Inno's silent switches, so none are specified.
* **`ProductCode: {…}_is1`** — Inno registers its uninstall entry under
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\{AppId}_is1`. This is how winget
  detects an existing install and offers `winget upgrade`; it must match `AppId` in `nib.iss`.
* **`MinimumOSVersion: 10.0.19041.0`** — Windows 10 2004. A conservative declared floor rather
  than a tested one; the app is developed and tested on Windows 11.

## Expect friction on the first submission

The binaries are **not code-signed**. winget-pkgs accepts unsigned installers, but its validation
pipeline runs Microsoft Defender and SmartScreen reputation checks against the URL, and a brand-new
unsigned executable with no download history is the exact profile that trips them. If validation
flags it, the fix is signing (see the launch checklist) rather than a manifest change.
